# AgriSage AI — Architectural Decision Record (`docs/DECISIONS.md`)

**Yuktik 2026 Hackathon | Technical Decisions & Rationale**

In accordance with the **Decision Rule**, reasonable technical choices are made autonomously and recorded below with concise justifications.

---

| ID | Title / Area | Decision Summary | Rationale / Trade-offs |
|---|---|---|---|
| **ADR-01** | Python Runtime Environment | Create backend virtualenv strictly using `py -3.12 -m venv .venv`. | Default Python on the host is 3.14, which lacks pre-compiled wheels for essential ML/CV libraries (e.g. PyTorch, torchvision, C-extensions). |
| **ADR-02** | Database Engine | Use SQLite managed via SQLAlchemy 2.0 ORM. | Self-contained, zero external daemon setup, fully portable on Windows, fast for testing, and sufficient for hackathon multi-user evaluation. |
| **ADR-03** | Evapotranspiration Model | Use FAO-56 Single Crop Coefficient ($ET_c = K_c \times ET_0$) rather than dual $K_c$. | Scientifically robust, well-documented FAO baseline that requires only reference $ET_0$ and growth stage $K_c$, avoiding spurious soil evaporation parameters without field sensors. |
| **ADR-04** | Plant Disease CV Model | Deploy a pretrained PlantVillage classification model for CPU inference with an input quality gate. | Free public model running fast on CPU; coupled with mandatory lab-image disclaimers and low-confidence "uncertain" fallbacks. |
| **ADR-05** | Pluggable Soil Health Card OCR | Pluggable OCR interface (EasyOCR, Tesseract, or Vision LLM) with a mandatory human confirmation UI. | Tesseract requires a native Windows install which may be absent; values are confirmed by the farmer before saving, preventing silent OCR error propagation. |
| **ADR-06** | Spatial Privacy & Outbreak Mapping | Restrict location telemetry to village centroids; enforce minimum 3-report cluster threshold on Outbreak Map. | Prevents exposure of exact farm boundaries and contact data to non-consenting users while preserving regional epidemiological awareness. |
| **ADR-07** | Global Multilingual Voice Assistant | Implement Voice Assistant as a global floating component on every page with browser Web Speech API and typed chat fallback. | Empowers non-literate and regional language farmers (`te`, `hi`, `en`) across any view without requiring expensive cloud speech API keys; degrades cleanly if mic is blocked. |
| **ADR-08** | Universal Explainability Schema | Mandate `{value, confidence, reasons[], sources[], status, limitations[]}` on all advisory payloads. | Eliminates black-box AI outputs and enforces hackathon honesty by presenting traceable scientific or meteorological reasoning on every recommendation. |
| **ADR-09** | Financial Precision | Enforce Python `Decimal` for all cost-of-cultivation, revenue, profit, and break-even calculations. | Eliminates binary floating-point rounding anomalies in agricultural accounting, especially when dividing acres and quintals. |
| **ADR-10** | Scope Guard Enforcement | Enforce strict Tier 1 completion prior to beginning Tier 2, and Tier 2 before Tier 3. | Prevents spreading effort across unfinished surfaces; ensures the core vertical slice and demo story are production-grade first. |
| **ADR-11** | Direct `bcrypt` Hashing | Use the `bcrypt` package directly without `passlib`. | Eliminates passlib's legacy bcrypt backend incompatibilities and ensures clean salt generation and verification under Python 3.12. |
| **ADR-12** | Demo Mode Security Boundary | Restrict passwordless `/api/v1/auth/demo-login` exclusively to Farmer Ramesh when `DEMO_MODE=true`. | Prevents privilege escalation; Admin, Expert, and Buyer accounts must authenticate via explicit credentials seeded in `.env.example`. |
| **ADR-13** | Absolute SQLite Path & Secret Guard | Resolve `SQLITE_DB_PATH` to an absolute path and enforce startup abortion if placeholder JWT secret is used when `DEBUG=false`. | Guarantees database file location remains stable regardless of process working directory and prevents insecure production deployments. |
| **ADR-14** | JWT Client Storage Strategy | Store JWT token and current session in browser `localStorage` (`agrisage_token`). | Provides seamless persistence across SPA page reloads and mobile browser tab refreshes for farmers with intermittent connectivity. Automatically cleared on 401 response and on user logout; avoids complex cross-origin cookie setup for local hackathon demo. |
| **ADR-15** | Orchestrator Shared `run_id` UUID Correlation | Generate a shared `run_id` (UUID v4) for each orchestrator run and persist it on every downstream agent row in `agent_runs`. | Enables correlation of multi-agent traces in a single query (`/api/v1/agents/runs/{run_id}`) without requiring complex join tables in SQLite, providing full execution timelines. |
| **ADR-16** | Non-Weather Agent Preview Stubs & Honesty Rules | In Phase 3.1, Irrigation, Disease, Yield, and Advisory agents operate in stub mode returning `null` for numeric prediction metrics with `status="stub"`. | Strictly prevents the fabrication of simulated numbers (yields, water volumes, health scores) before ML model activation in Prompts 3.2–3.5, complying with Yuktik Honesty Rules while allowing live conflict and telemetry orchestration. |
| **ADR-17** | Pretrained MobileNetV2 PlantVillage Model Selection | Selected `neghani/plantvillage-mobilenetv2` (Apache-2.0, commit `d33601185b32cf05b3942661b8d84ffb86dc48ec`, weights 9.26 MB) for foliar classification across 38 classes. | Lightweight, fast CPU inference (<150ms per forward pass), zero GPU requirement, clean safetensors distribution. The 14 supported crops are explicitly surfaced; unsupported crop hints (Cotton, Chilli, Rice, Wheat) produce visual similarity matches with mandatory mismatch warnings rather than misleading high confidence. |
| **ADR-18** | Multi-Factor Input Quality Gate Heuristics | Filter images before inference using 4 heuristic tests: resolution ($\ge 64\times 64$), mean luminance ($20.0 \le \mu \le 240.0$), Laplacian edge variance ($\ge 60.0$ on $224\times 224$), and foliar chromaticity ($(R+G) > 1.2\times B \ge 0.20$). | Prevents forcing garbage inputs (blurry photos, darkness, screenshots, desks) into crop disease labels. Formulating foliar chromaticity as $(R+G) > 1.2\times B$ ensures chlorotic, necrotic, and brown-spotted diseased leaves pass with $>95\%$ ratios while rejecting non-vegetative surfaces. |
| **ADR-19** | Ephemeral Leaf Image Ingestion & Anonymized Outbreak Telemetry | Never persist uploaded leaf photos to permanent storage; discard immediately after inference from memory. Only save disease reports if user explicitly opts in (`report_to_outbreak=true`, unchecked by default), storing only village centroid metadata. | Protects farmer privacy and prevents storage exhaustion from high-resolution leaf photos. Preserves spatial anonymity by omitting precise GPS coordinates from outbreak clustering. |
| **ADR-20** | Independent Weather Fungal Risk Factor | Relative humidity ($\ge 80\%$) and rainfall ($\ge 15\text{ mm}$ in 24h) trigger an elevated fungal sporulation risk warning that is evaluated separately and NEVER modifies the vision model's uncalibrated softmax probability. | Prevents artificial inflation or suppression of empirical neural network outputs with heuristic environmental factors, maintaining clear provenance between visual evidence and atmospheric risk. |
| **ADR-21** | Pre-Phase 3.3 Cleanup: Fixtures Static Mount Removal, UI i18n Audit, and KB Citation Verification | Removed `/fixtures` StaticFiles mount from `backend/app/main.py`; replaced all hardcoded UI strings across frontend with multilingual keys (`en`, `te`, `hi`); verified all URLs in `disease_kb.json` via live web fetch. | Fixtures are loaded directly from disk in test suites; removing static mount eliminates unnecessary production exposure. Replacing hardcoded UI strings ensures authentic multilingual access; read-aloud TTS now checks OS voice pack availability and alerts if missing. Unreachable institutional domains and generic landing pages in `disease_kb.json` were removed and their status marked 'to verify' per Yuktik Honesty Rules. |
| **ADR-22** | FAO-56 Single $K_c$ Irrigation Engine & Soil Finger Test Advisory | Implemented FAO-56 single crop coefficient model ($ET_c = K_c \times ET_0$) across 4 growth stages for 10 major Indian crops, AWC bucket balance, method efficiencies (drip 90%, sprinkler 75%, furrow 60%, flood 50%), rain-skip water conservation, multilingual keyword problem diagnosis (`en`, `te`, `hi`), and in-field finger moisture test guide. | Provides rigorous, science-grounded crop water budgeting without guessing soil sensors; rain-skip conserves groundwater pumping when $\ge 15\text{ mm}$ rain is forecast. Never claims photos measure soil moisture (labels photo analysis as "visual indication only, not a soil moisture measurement", marks status `PARTIAL`, and provides direct tactile 4-step finger test guide). |
| **ADR-23** | Crop Recommendation Classifier, Multi-Quantile Yield Regressor & Honest Baseline Evaluation | Implemented RandomForest classifier (22 crops, 99.39% holdout accuracy) with weather-only fallback variant (92.73% holdout accuracy) and rule-based climate suitability filter. Implemented HistGradientBoosting multi-quantile regressor ($q_{10}, q_{50}, q_{90}$) on 202,591 records (1997–2012 train, 2013–2015 test) using TargetEncoder for 639 districts and pre-bifurcation Telangana data (Hanamkonda $\to$ Warangal). Strictly excluded non-tonne crops (Coconut, Cotton, Jute, Mesta, Sannhamp) with explicit `PARTIAL` notices. Honestly disclosed that the ML model does not beat the historical district-mean baseline on point accuracy (MAE 6.45 vs 4.57 q/acre). Labeled all dynamic heuristic adjustments (fungal infection -10%, moisture stress -8%, waterlogging -12%) as 'indicative assumption, no source'. | Complies with Yuktik Honesty Rules by avoiding synthetic or invented soil data, reporting genuine holdout metrics, acknowledging baseline superiority on point predictions, providing calibrated empirical interval coverage (77.26%), protecting against agro-climatically absurd recommendations (apple/coffee in southern plains), and declaring unmodelled staple crops. |
| **ADR-24** | Phenological Growth-Stage Engine, Advisory Coordinator Agent & Farm Health Score | Implemented 5-stage phenological growth engine (`germination`, `vegetative`, `flowering`, `fruiting`, `maturity`) mapped onto FAO-56's 4 stages (`initial`, `development`, `mid`, `late`), reusing exact stage lengths from `fao56_crop_coefficients.json` for 10 crops and labeled 'indicative mapping onto FAO-56 4-stage model, to verify'. Implemented Advisory coordinator agent synthesizing Weather, Irrigation, Disease, Yield, and Phenology into a 7-day action plan with agent tracing and explainable 'Because...' rationales. Formulated a transparent 5-component Farm Health Score (Weather, Foliar Pathology, Water Status, Stage Appropriateness, Economics) with re-normalization over active components and an explicit cutoff: if $< 3$ components have data, returns `INSUFFICIENT_DATA` with `score=None`. Labeled all score thresholds as 'indicative, not validated'. Labeled all stage guidance, fertilizer timing, and spraying windows as 'general guidance, confirm with your local agriculture officer' with strictly zero chemical quantities. Cotton headline yield returns 'not supported' (bales, not tonnes). Recorded all newly introduced Telugu and Hindi phrases in `docs/I18N_REVIEW.md` as unverified. | Transparent, explainable, and scientifically honest agronomic coordination complying with Yuktik Honesty Rules. Prevents dangerous amateur chemical dosing; guarantees dashboard stage matches irrigation $K_c$ stage; prevents artificial or ungrounded health scores when telemetry is absent; ensures full auditability across all recommended daily tasks. |
| **ADR-25** | Decimal Cost-of-Cultivation Engine, Tenure Separation Math, What-If Simulator, Rule-Based Rotation, and RFC 5545 Calendar | Enforce Python `Decimal` across all monetary arithmetic; model owned ($₹0$ lease) and leased land as separate cost centers before combining for mixed tenure ($A_{\text{owned}} + A_{\text{leased}} = A_{\text{total}}$). Mark prices as 'price: your estimate' and 'MSP not verified'. Rewrite cost template sources to state plainly: 'Indicative estimates entered by the project team, not taken from any published report; edit to your actual cost; verify with your local KVK or agriculture officer', keeping 'indicative estimate, edit to your actual cost' in API and UI. Cotton yield is user-entered; other crops use district mean baseline. Client-side What-If formula verified against backend parity test. Rule-based crop rotation enforces biological nitrogen fixation and pest-cycle breaks while flagging monoculture (Cotton, Solanaceae, Okra) with all citations marked 'to verify - source not checked' and figures labeled 'indicative, to verify' with zero unconfirmed document titles. Calendar engine models 7 lifecycle stages and generates RFC 5545 compliant `.ics` feeds with CRLF line endings. Integrated economic health into Farm Health Score (10% nominal weight) adhering strictly to exclude-if-missing rule. | Eliminates floating-point rounding errors in agricultural budgeting; prevents fraudulent market or yield claims; gives tenant and mixed-holding farmers truthful accounting of high lease burdens; empowers farmers with cross-platform digital calendar task tracking without claiming unverified institutional sources. |
| **ADR-26** | Multilingual Voice Assistant Architecture, Capability Detection, Safe Prescriptions, and Typed Fallback | Implemented global floating Voice Assistant mounted via `#global-voice-assistant-slot` across every page. Client-side speech-to-text uses Web Speech Recognition with `en-IN`, `te-IN`, `hi-IN` matched to language; speech-to-text synthesis uses `speechSynthesis` with language-specific voice priority matching. Capability detection checks for browser speech API and voice availability; if unsupported or permission is denied, displays non-intrusive warning advisory, explains that Chrome on Android/Desktop works best, and maintains 100% functionality via typed chat input. Backend `POST /api/v1/voice/query` enforces user authentication, classifies queries into 7 intents (`weather`, `irrigation`, `disease`, `cost`, `scheme`, `price`, `general`) via multilingual rules, routes to live farm services (Open-Meteo, FAO-56 balance, Economics, Disease KB), and returns spoken-length advice. Enforces safety sanitizer strictly banning chemical dosages and yield guarantees. In scheme intent, strictly avoids naming specific schemes, amounts, or eligibility from memory, answering that scheme details change, the in-app list is not built yet, and directing the farmer to the local Mandal agriculture office or official portal, labeled 'details to verify' (status `PARTIAL`). General intent routes to Gemini API only when `GEMINI_API_KEY` is present under strict agricultural constraints; otherwise falls back gracefully to 'I don't know, please consult an agriculture officer' (with Telugu and Hindi equivalents). Mandi price queries state honestly that market data is not available yet. All UI text translated into `en`, `te`, `hi`, with new terms cataloged in `docs/I18N_REVIEW.md`. | Directly empowers smallholder farmers across India with vernacular voice interaction while strictly respecting browser capabilities, user privacy, and safety rules; never fabricates market prices, unverified scheme figures, or chemical prescriptions; provides robust typed fallback on any desktop or mobile device. |
| **ADR-27** | Fix for BUG 4: FAO-56 Crop Water Budget Calculation & Direct Sub-Button Telemetry Rendering | Placed the primary "Compute Crop Water Budget" action button directly on the Farm Calibration panel, added smooth scrolling to results ref, added empty/loading/error states, persisted last plan in localStorage (`agrisage_last_irrigation_plan`) across SPA navigations, rendered explicit ET0, ETc, DAS, stage, Kc, trigger condition, why rationale, StatusBadge, and mandatory honesty note "Soil moisture is modelled, not measured. Confirm with physical soil inspection before irrigating". Backend respects active farm parameters while allowing user field overrides. | Guarantees clear visual feedback and immediate rendering under the calculate button without requiring users to search the header; prevents missing metrics or silent blank states on network or session errors; complies with Yuktik Honesty Rule 3 regarding modelled soil moisture. |
| **ADR-28** | Fix for BUG 5: What-If Profit Simulator Reactive Architecture & Backend Formula Parity | Rebuilt What-If simulator around a pure function `computeProfit(inputs)` executing instantaneously across client and backend. Backend calls to `simulateWhatIf` are debounced (350ms). | Eliminates unresponsive slider controls and state disconnection; guarantees immediate visual feedback on any input adjustment; ensures mathematical exactness between client and server Decimal calculations; prevents UI freeze or server flooding via debouncing. |
| **ADR-29** | Fix for BUG 1: Multilingual Voice Assistant Greeting Handlers, Intent Modularity, Voice Synthesis Guard, and Safe Small Talk | Refactored voice keywords and small-talk dialogues into modular language files (`backend/app/keywords/{en,te,hi}.py`). Added dedicated intent classification and responses for greetings (`hi`, `hello`, `namaste`, `నమస్కారం`, `నమస్తే`, `హలో`), assistant intro (`who are you`), appreciation (`thanks`), and departure (`bye`).
